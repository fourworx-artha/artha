# Session 24 — 2026-06-11

## What was accomplished

**W1–W5 consistency audit + fixes for the top 5 findings.** Full read-through of all code shipped in W1–W5 (engine, operations.js, W2 RPC SQL, DeviceGate, Dashboard auto-run, OnboardingFlow, Backup, Members, seed, contexts). 18 findings (A1–A18) documented in a new **"🔍 W1–W5 Consistency Audit"** section in `docs/handoffs/HANDOFF.md`, ranked by severity. A1–A5 fixed and verified this session; A6–A18 remain open.

**Fixed:**

- **A1 (critical)** — New onboarded families produced NaN payslips: W5's Starter config omits the stage-gated keys but W6's `ENGINE_DEFAULTS` layer didn't exist, so `net * config.autoSavePercent` → NaN → corrupt draft → corrupt `members.accounts` at settle. Fix: `ENGINE_DEFAULTS` pulled forward into `src/engine/payslip.js`; `calculatePayslip` now resolves `{ ...ENGINE_DEFAULTS, ...familyConfig }`. Combined with `runPayslip`'s existing `{ ...family.config, ...member.config }` merge this is exactly the W6 three-layer resolution — **W6 STEP 0 is effectively done**. Regression test added (Starter-shaped config → finite values, zero allocations).
- **A2 (critical)** — W4 device self-migration never fired: `App.jsx` checked `cached?.family_id` but cached claims are stored camelCase. Fixed to `cached?.familyId`; pre-W4 devices now backfill `artha_family_id`.
- **A3 (critical)** — First-settle teaching prompt unreachable: starter config wrote `autoSettle: false` but the prompt only fires while the key is `undefined`. Removed `autoSettle` from the starter config (amends session 23's documented config) and deleted the dead prompt check inside Dashboard's auto-settle branch.
- **A4 (high)** — Legacy accounts shape bricked money ops: `Members.jsx` and `seed.js` created members as `{ spending, savings, goalJar }`, which W1's `validateAccounts` rejects on any subsequent `updateMemberAccounts` (giveBonus, rewards, transfers all threw). Fixed all creation sites to the canonical shape (keeping `goalJar` — still a live feature); the Members edit path now spreads canonical defaults first so legacy rows **self-heal on save**; `updateMember` now validates `accounts` (bypass closed).
- **A5 (high)** — Backup restore corrupted data: import dropped W2 columns (drafts came back looking "settled" with unapplied balances) and read `r.cost` although export maps `cost → price` (all reward prices nulled). Fixed: backup format **v4** — import restores `status`/`pending_transactions`/`credit_delta`/`bonus_potential`, reward mapping is `r.price ?? r.cost ?? 0`, and `member_requests` are now exported/cleared/re-inserted. `join_codes`/`device_claims` deliberately excluded (device-bound).

**Verification:** 13/13 vitest pass (12 existing + 1 new), production build clean, `graphify update` run.

## Decisions made

- **ENGINE_DEFAULTS pulled forward (W6 STEP 0), with one interim deviation:** `streakBonusEnabled` defaults **true**, not `false` as the W6 spec says — no existing family config has the key, so `false` would have silently disabled streak bonuses for the live family. W6 stage patches must flip it to `false` once member.config backfill exists (recorded in code comment + handoff).
- **`autoSettle` stays out of the starter config** so the W3 first-settle prompt can fire (amends session 23's starterConfig spec).
- **Backup format v4**; `join_codes`/`device_claims` are deliberately never part of backups.
- **Legacy-shaped members heal lazily** (on Members-edit or settle) rather than via a one-off migration — pre-fix parents keep the old shape until edited, harmless since no money ops target parents.
- **A10 (EconomicControls wiping `member.config`) is folded into W6**, not fixed standalone — W6 redesigns that write path anyway.
