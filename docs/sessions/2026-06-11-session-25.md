### Pre-W6 family self-migration (`migrateStageConfig`)
One-shot, idempotent, called from `FamilyContext.loadFamily` (any device heals the family). Copies each child's **effective** values (family.config first, patch defaults as fallback) into `member.config` for the keys their stage has unlocked, then strips the four stage-gated keys from `family.config`. Behaviour-preserving for Economist children — which is what the live family's children are. Gate: runs only while `family.config` still has a stage-gated key.

## Decisions made
- **No tier filter in stage logic**: docs distinguish Tier 1 (coin jar) / Tier 2 (payslip), but the codebase has no tier concept — every `role === 'child'` member is a payslip child, so stages apply to all children. A future Tier 1 mode would add a `tier` field and be excluded then.
- **Pre-W6 migration copies effective values, not patch defaults** — `member.config[key] = family.config[key] ?? patchDefault` — so the live family's actual configured rates survive the move; then family.config is stripped of the four stage-gated keys. Runs from any device, one-shot.
- **Advancement applies the cumulative patch** (through the new stage), not just the single stage's keys — idempotent and self-healing; `configTouched` protects parent edits either way.
- **Settled-count query treats NULL status as settled** (`.or('status.eq.settled,status.is.null')`) — pre-status-column rows must count or the live family's children would derive the wrong stage.
- **`settlePayslip` return shape** is now `{ settled, stageAdvanced }` (all current callers ignore the return; W9 consumes `stageAdvanced`).
- **GiveMoneySheet loan tab gated per child stage** (not in spec's list, but a loan given to a pre-Economist child would be invisible to them — extended "loans = Economist" consistently).
